00.1

Comment lire ce document

designer

Les fondations fixent ce qui est décidé une fois pour toutes. Chaque composant donne son anatomie, ses variantes, ses états et ses mesures. Aucune valeur en dehors des échelles listées ne doit apparaître dans une maquette.

développeur

Les tokens sont la seule source de valeurs. Chaque composant donne son API, son balisage de référence et ses exigences d'accessibilité. Une valeur en dur dans un composant est un défaut de conformité.

notation
  • obligatoire — doit
  • recommandé — devrait
  • interdit — ne doit jamais
00.2

Principes de conception

  1. Une chose, bien faiteUne application répond à une question. Une fonctionnalité qui ne sert pas cette question n'est pas ajoutée.
  2. Le texte d'abordTexte, ligne, point, espace. Toute autre primitive doit être justifiée.
  3. La couleur est un renfortAucune information ne dépend de la couleur seule. Le monochrome est l'état par défaut.
  4. L'espace avant la boîteOn dépense de l'espace avant d'ajouter une bordure, une carte, une ombre ou une icône.
  5. Local par défautOffline-first, aucune dépendance réseau implicite, aucun compte obligatoire.
  6. Le clavier est prioritaireTout parcours réalisable à la souris est réalisable au clavier, avec un focus visible.
01.1

Couleur

Quatre rôles sémantiques, deux thèmes. Le rôle est stable, la valeur change avec le thème. Un composant ne référence jamais une valeur : il référence un rôle.

color-ink#17181a#ecebe6 16.3:1 / 15.5:1 — texte principal, AAA

color-muted-strong#6a6c6a#8e9089 4.8:1 — texte secondaire < 16px, AA

palette d'accent — une seule active à la fois
  • mono
  • sage
  • blue
  • violet
  • orange
  • coral
  • graphite

Contrainte : tout accent doit atteindre 4.5:1 sur --color-bg dans les deux thèmes.

dark — parité de rôles

Le thème sombre est une palette conçue, pas une inversion. Les rôles, les épaisseurs de trait et les états restent identiques ; seules les valeurs changent.

01.5

Mouvement

Propriétés animables : opacity, transform. Interdites : width, height, top/left, color de fond sur de grandes surfaces. Sous prefers-reduced-motion: reduce, les durées passent à 0 et les transitions deviennent des changements d'état immédiats.

Toute icône hors de ce jeu doit être validée en revue. Une icône n'est jamais seule porteuse d'action : elle accompagne un libellé ou porte un aria-label. Aucun emoji, aucune icône décorative.

02.1

Tokens — modèle & nommage

niveau 1 — primitif

Valeur brute. --grey-850: #17181a. Jamais utilisé dans un composant.

niveau 2 — sémantique

Rôle. --color-ink: var(--grey-850). Change avec le thème.

niveau 3 — composant

Décision locale. --button-height: 44px. Ne référence que le niveau 2.

Convention : --{catégorie}-{rôle}-{variante}, en minuscules, séparé par des tirets, en anglais. Les mêmes noms sont utilisés dans Figma (variables) et dans le CSS — un renommage se fait des deux côtés dans la même version.

03.2

TextField

stable · 1.1

Saisie d'une valeur courte sur une ligne. Le label est toujours visible ; le placeholder ne remplace jamais le label.

anatomie
  1. 1 label — text-meta, muted, obligatoire
  2. 2 champ — hauteur 44, padding-x 12, radius 4, trait 1 px rule
  3. 3 aide — text-meta, muted-strong, sous le champ
  4. 4 erreur — remplace l'aide, --color-danger + texte
  5. 5 effacement — bouton 42 × 42 dans le champ, à droite, visible quand la valeur n'est pas vide
états
API
proptypevaleursdéfaut
labelstringrequis—
value / onChangestring / fncontrôlé—
hintstring—null
errorstringmessage complet, pas un codenull
clearablebooleanbouton × dessiné, jamais le rendu natiffalse
inputModeenumtext · numeric · nonetext

Accessibilité — <label for> lié à l'id, aria-describedby vers l'aide, aria-invalid et message annoncé en role="alert" à la validation. Erreur affichée après soumission ou perte de focus, jamais à chaque frappe. Le bouton d'effacement porte aria-label et rend le focus au champ ; il est positionné en absolu dans le champ pour que son apparition ne décale rien.

03.3

Toggle

stable · 1.1

Change un réglage à choix fermé, appliqué immédiatement. Représenté par un mot d'état qui défile au clic, pas par un interrupteur graphique. Une phrase de 12 px sous le groupe explique la mécanique : la règle « le libellé dit ce qui se passe » vaut aussi pour un contrôle qu'on découvre.

thème sombresystème
semaine commence lelundi
notificationsindisponible hors ligne
spécification
  • ligne de 44 px minimum, cible = toute la ligne
  • valeur alignée à droite, text-data
  • cycle des valeurs au clic, Entrée et Espace
accessibilité
  • <button> simple dont le nom accessible porte la valeur : « thème : système, changer »
  • ni role="switch" ni radiogroup — un bouton qui fait défiler n'est ni l'un ni l'autre
  • l'état est lu comme texte, pas comme couleur

stable · 1.1

Unité de liste : une clé, un marqueur, un contenu. Base de DayRow (month.) et des lignes de réglages. C'est le composant le plus utilisé de la famille.

03.5

Dot

stable · 1.1

Marqueur atomique de la famille : présence d'un événement, d'une action réalisée, d'une identité. Jamais un badge, jamais un compteur.

filled / 6 px
fait, présent
outline / 6 px
prévu, à venir
large / 8 px
identité, marque
série / gap 4
3 maximum, puis « +n »
trait
continuation multi-jours
liaison point ↔ trait
14 venGolf trip
15 samsuite
16 dimfin
  • colonne de marqueur en position:relative, largeur 16, align-self:stretch — sans hauteur résolue, top/bottom n'ont rien contre quoi se calculer
  • point et trait partagent le même axe : point à left:0 (6 px), trait à left:2px
  • le trait déborde du padding de la ligne (bottom:-10px) pour franchir le séparateur : la continuité doit être visible d'une ligne à l'autre
  • dernier jour d'une série : le trait s'arrête à la hauteur où serait le point

Le point n'est jamais seul porteur d'information : il est doublé d'un texte, d'un aria-label ou d'un décompte lisible. Zone tactile parente de 44 px minimum.

03.6

PeriodNav

stable · 1.1

Navigation temporelle : précédent, période courante, suivant. Une seule instance par écran, en haut du contenu.

large — période courante
‹ juillet août 2026aujourd'hui septembre ›
étroit — période éloignée
‹ mars 2024revenir à aujourd'hui ›
comportement
  • libellés adjacents nommés, pas « précédent »
  • sous 480 px : libellés réduits aux chevrons (44 × 44, aria-label nommé), titre en nowrap
  • le titre EST le retour à la période courante : bloc titre + légende, une seule cible
  • légende permanente de 12 px sous le titre — « aujourd'hui » sur la période courante, « revenir à aujourd'hui » ailleurs. Elle ne disparaît jamais : rien à deviner, aucun décalage de mise en page
clavier
  • ← / → changent de période
  • T revient à aujourd'hui
  • changement annoncé via aria-live="polite"
03.7

SearchFilterBar

stable · 1.0

Réduire une liste longue : un champ de recherche libre et un filtre à choix fermé, sur une seule rangée de 44 px, directement sous le titre de la vue.

éléments 4 sur 12 · date ↓
×
tous les types ⌄
spécification
  • recherche = TextField clearable, placeholder listant les champs couverts, sans le mot « rechercher »
  • filtre à choix fermé = <select> natif dès 4 valeurs ou plus : tient sur une ligne quel qu'en soit le nombre
  • en dessous de 4 valeurs courtes : libellés texte, actif souligné 1 px
  • décompte « N sur M » dans la ligne de titre, jamais sur une ligne à part
règles
  • aucun contrôle conditionnel dans la barre : un élément qui apparaît décale la liste
  • remise à zéro par les affordances existantes — le × du champ, l'option « tous » du select
  • « effacer les filtres » n'existe que dans l'EmptyState « aucun résultat », où rien ne se décale
  • filtrage immédiat à la frappe, décompte en aria-live="polite"

04.2

Données, i18n, persistance

formats
  • dates stockées en ISO 8601 AAAA-MM-JJ
  • affichage via Intl.DateTimeFormat selon la locale
  • premier jour de semaine issu de la locale, surchargeable
  • aucune date formatée en base
i18n
  • FR / EN / System, clés domaine.composant.clé
  • aucun texte en dur dans un composant
  • prévoir +30 % de longueur de libellé
  • pluriels via Intl.PluralRules
export / import
{
  "schemaVersion": 1,
  "data": {},
  "settings": {}
}

Import validé contre le schéma, migration explicite entre versions, jamais d'écrasement silencieux : l'utilisateur choisit fusionner ou remplacer.

05.2

Versions & contribution

versionnage — semver
  • majorrupture : token supprimé ou renommé, API modifiée
  • minorajout rétrocompatible : composant, variante, token
  • patchcorrection visuelle ou d'accessibilité

Un token déprécié reste disponible une version majeure, marqué @deprecated.

ajouter un composant
  1. 1 prouver que trois écrans en ont besoin
  2. 2 vérifier qu'aucune composition existante ne suffit
  3. 3 documenter anatomie, états, API, a11y
  4. 4 revue design + dev, une seule passe
  5. 5 publier en minor, mettre à jour cette page

Une fonctionnalité ne crée pas automatiquement un composant.
